# Synthetic Data Generation Plan

## Context

**Source data facts** (from data dictionary analysis):
- 3 products, 4 locations, 83 vehicles, 83 shipments, 159 product-shipment lines
- Date window: depart Apr 7-11, arrive Apr 17-29 (all 2024)
- Locations: Houston (30 origins, 16 dests), St. Louis (32 origins, 7 dests), Chicago (14 origins, 26 dests), New York (7 origins, 34 dests)
- Products per shipment: 32 have 1, 26 have 2, 25 have 3

**Output target:** `data/synthetic/` (directory exists, empty). One Python script `src/generate_synthetic.py`, five output CSVs.

## Implementation: Single Python script `src/generate_synthetic.py`

### Global seed: `SEED = 42` (documented at top of file)

### Entity 1: SUPPLIERS (6 suppliers)
- **Count logic:** 2 suppliers per product (primary + alternate) = 6 total
- **Deterministic mapping:** `product-1 → supplier-1 (primary), supplier-2 (alt)`, etc.
- **Attributes:** supplier_id, supplier_name, region (APAC/EMEA/AMERICAS round-robin), reliability_score (0.80-0.98 from seed), lead_time_days (5-25 from seed), tier (Tier1/Tier2 alternating)
- **Output:** `data/synthetic/synthetic_suppliers.csv`

### Entity 2: CUSTOMERS (8 customers)
- **Count logic:** 2 per destination location (4 locations × 2 = 8)
- **Deterministic mapping:** destination_location hash → customer assignment
- **Segments:** Strategic (top 2 by shipment volume), Premium (next 3), Standard (remaining 3)
- **Attributes:** customer_id, customer_name, location_id, region, segment
- **Output:** `data/synthetic/synthetic_customers.csv`

### Entity 3: ORDERS (83 orders, 1:1 with shipments)
- **Relationship:** Each shipment gets exactly one order. `order_id = 'ORD-' + shipment_name_number`
- **customer_id:** Deterministic from destination_location → pick customer using `hash(shipment_id) % 2`
- **order_date:** `departing_origin_date - offset` where offset = `hash(shipment_id) % 5 + 1` days (1-5 days before departure)
- **requested_delivery_date:** `arriving_destination_date + jitter` where jitter = `[-2, -1, 0, 0, 0, +1, +2, +3]` selected by `hash(shipment_id) % 8`. This creates ~37% late, ~37% on-time, ~25% early deliveries
- **ordered_quantity:** `total_unit_quantity + surplus` where surplus = `hash(shipment_id) % 3 * 1000` (0, 1000, or 2000 extra)
- **priority:** High/Medium/Low based on `total_unit_quantity` terciles
- **status:** All \"Completed\" (shipments are all scheduled, orders precede them)
- **Output:** `data/synthetic/synthetic_orders.csv`

### Entity 4: COSTS (per product_shipment row = 159 rows)
- **unit_cost:** Fixed per product: product-1=12.50, product-2=8.75, product-3=15.00
- **freight_cost:** `base_freight_per_route + (quantity / 1000) * 2.50` where base_freight is a fixed lookup by (origin, destination) pair using haversine-proportional values
- **duty_cost:** `quantity * duty_rate` where duty_rate is fixed per product (0.03, 0.05, 0.04)
- **handling_cost:** `150.00 + quantity * 0.02` (fixed base + per-unit)
- **landed_cost:** `(unit_cost * quantity) + freight_cost + duty_cost + handling_cost`
- **Output:** `data/synthetic/synthetic_costs.csv`

### Entity 5: INVENTORY SNAPSHOTS (30 days × 4 locations × 3 products = 360 rows)
- **Date range:** 2024-03-12 to 2024-04-10 (30 days ending at last departure)
- **daily_demand:** Fixed per (location, product) pair, seeded. Range 200-800 units/day
- **opening_inventory:** 15000 per (location, product) on day 1
- **Daily formula:** `inventory[d] = inventory[d-1] - daily_demand + inbound_shipments_arriving_on_d`
- **Floor at 0** (no negative inventory)
- **Output:** `data/synthetic/synthetic_inventory.csv`
